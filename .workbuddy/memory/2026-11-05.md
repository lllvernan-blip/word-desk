## 发音与词库两个问题的解决办法（未改 dist/）
- 用户就「单词发音」「词库」两个问题要解决方案，本轮只做诊断、实测、出方案与交付物，dist/ 零改动。
- 关键实测纠正了 11-04 的乐观结论：api.dictionaryapi.dev 的 JSON 接口 CORS 可用但 30 词抽样仅 15/30 成功、总耗时 52.5s；其真人 mp3 直链连续 3 次 502、GET 超时，稳定不可用。原先选定的「在线真人音频 + 本地缓存」不成立。
- 备选实测：有道 dictvoice 200 / 0.1–0.65s / 11–33KB / audio/mpeg，但无 Access-Control-Allow-Origin（无法 fetch 存 IndexedDB）、非公开接口、偶发 SSL 失败；Wikimedia Commons 真人录音直链 200 / 10–14KB / CC BY-SA，但按文件名规则盲猜命中率仅 6/30=20%，必须先建索引。
- 发音三方向：A 离线真人音频包（推荐，P0，400 词约 5MB / 全库约 40MB）、B 在线合成音（改动最小、不能缓存）、C 混合。选 A/C 才能把 FEATURES.listenDictation 与 followRead 改回 true。
- 词库现状：3400 词、音标 3377、词频 3000、考试标签 2960、多义项 1724；英文释义/例句/同义反义/真人发音全为 0；词缀 842、词根 119；content 热更新 8 条里 5 条与精选重名。
- 词库四层问题：内容层缺详情、结构层生成脚本缺失、链路层 P1-2 热更新部分失败即提交 / P1-3 远端覆盖精选 / P2-5 sha256 未校验、使用层自建词库无导出备份。三方向：乙 修可维护性（P0，先做）→ 甲 补内容（P1）→ 丙 扩规模（P2 暂缓）。
- 统一判断：纯静态 PWA 不该实时调外部 API，应走离线预生成数据包 + 按需加载 + 本地缓存，与现有 content/ 架构一致。
- 交付：output/单词翻译练习台_发音与词库_解决方案_2026-11-05.docx（五节方案简报，含实测表、方向对比、优先级与影响范围、实施清单、待拍板三项）；output/brief-compose/ 对应 HTML 中间产物；output/pronunciation-ab/index.html（四组真人/合成 A/B 试听页 + 7 个音频样本，hello 的在线源本次抓取失败）。
