发音与词库两个问题的解决办法

单词翻译练习台 · 技术方案简报 · 2026 年 11 月 5 日 · 本轮未改动 dist/ 任何文件

一、结论先行

  1. 两个问题指向同一个前提，都不适合实时调用外部词典接口。11 月 5 日实测外部接口成功率 50%、单请求平均 1.7 秒以上、真人音频直链连续三次返回 502。纯静态 PWA 应改成离线预生成数据包、按需加载、读过后存本地缓存，这与项目现有 content/ 热更新架构一致。
  2. 发音原先选定的「在线真人音频 + 本地缓存」在当前网络条件下不成立，需要重新选路线。
  3. 词库问题分四层，建议先修可维护性，再补内容，规模扩张暂不做。

二、问题一 · 单词发音

2.1 现状

  1. FEATURES.listenDictation 与 FEATURES.followRead 均为 false，听音拼写与跟读自评整体下架，答题遇到 listen 步骤降级为普通拼写。
  2. 唯一实现是系统 TTS（speechSynthesis + pickEnglishVoice）。中文系统环境下英文音质差，真机反馈听不出是什么，已被否掉。
  3. 代码注释写明等离线音频包 v1.5 一起恢复，离线包一直没有做。
  4. 3400 词里没有任何音频字段。音标覆盖 3377 词（99.3%），只有符号没有声音。

2.2 实测数据（2026-11-05，本地网络）

候选源结果判断
Free Dictionary API JSONCORS 为 *，约 1.6 秒；30 词分层抽样仅 15 词成功，其余 fetch failed，总耗时 52.5 秒不稳，不能实时用
该 API 真人 mp3 直链连续三次 502，GET 请求超时稳定不可用
Wikimedia Commons 真人录音直链 200，单文件 10 至 14 KB，CC BY-SA 授权；按文件名规则盲猜命中率仅 20%（30 词命中 6 词）可用，但要先建索引
有道 dictvoice200，0.1 至 0.65 秒，11 至 33 KB，audio/mpeg；无跨域头，非公开接口，偶发 SSL 失败快，但存不进本地缓存
系统 TTS全平台可用音质已被否

在线源没有 Access-Control-Allow-Origin，浏览器无法 fetch 到字节写 IndexedDB，所以「播放过即缓存」这条要求只有离线包能满足。

2.3 三个方向

方向做法优点代价
A 离线真人包（推荐）
P0		构建脚本按词库拉取 Commons 或 Wiktionary 真人录音，转 mp3，生成 content/audio-index.json 与 audio/ 随站点发布。首页只载索引，点播放才下载，播过存 IndexedDB真人音质、离线可用、同源无跨域限制、可恢复听音拼写与跟读自评首次需外部抓取与转码、需 CC 署名；体积估算 400 精选词约 5 MB，3400 全库约 40 MB；必须先解决索引命中率
B 在线合成音
P1		audio 标签直连有道，失败静默隐藏按钮改动最小、零体积、国内快合成音非真人、无授权无 SLA、无法本地缓存；建议只恢复听音拼写
C 混合
P1		精选 400 词离线真人包兜底，其余走在线，在线失败隐藏按钮体验最完整成本最高，两套链路都要维护

选 A 或 C 可把两个功能开关改回 true。选 B 建议只恢复听音拼写，跟读自评意义有限。

决策依据：output/pronunciation-ab/index.html 已放四组 A/B 试听样本，可直接点开对比。hello 一组在线源本次抓取失败，正好说明在线方案会偶发不可用。

3.2 四层问题

  1. 内容层。只有中文短译，缺英文释义、例句、同义词，词条详情页没有内容可展示。
  2. 结构层。words-core.js 与 roots-data.js 都标注脚本生成勿手改，生成脚本不在仓库，3400 词库无法再生成、校验或批量更新。
  3. 链路层。热更新部分 source 成功即写入最新版本号，缺词不可自愈（P1-2）；远端词覆盖精选词条，bilingual、semiautomatic、nonfiction、prehistoric、transatlantic 五条受影响（P1-3）；manifest 的 sha256 为空且未校验（P2-5）。
  4. 使用层。自建词库只有清空，没有导出与备份。

3.3 三个方向与影响范围

方向做法优先级影响文件
乙 修可维护性（建议先做）生成脚本放回仓库或新建 tools/build-words.js；统一词条 schema；补 sha256 校验；修 P1-2 与 P1-3；自建词库加导出备份。零外部依赖，不产生用户可见新内容，但它是方向甲的地基P0tools/（新增）、app.js、content/manifest.json
甲 补内容离线预生成词条增强包，按词分片 JSON 存 content/word-details/，补英文释义、例句、同义词，词条详情抽屉按需加载。成功的 15 词里 15 词有英文释义、13 词有例句，内容可得，但在线成功率仅 50% 且慢，必须预生成P1app.js、index.html、styles.css、content/
丙 扩规模与质量换或扩词库源，补词根词缀标注提升分类覆盖。改动面最大，需重新校验 3400 词练习逻辑，与朋友日常练习场景未必匹配P2 暂缓全量词库与筛选逻辑

推荐顺序：乙 → 甲 → 丙。乙不依赖外部数据、风险最低，还能给甲提供生成脚本；甲依赖乙；丙在场景明确前不做。

四、实施清单（确认路线后执行）

  1. 影响文件。dist/app.js（发音模块、词条详情、功能开关）、dist/index.html（播放按钮、详情抽屉、音频署名）、dist/styles.css、dist/content/（新增音频与词条数据）、dist/sw.js（缓存版本 v28 递增，新资源纳入缓存策略）、tools/（新增生成脚本）、AGENTS.md（同步缓存版本与目录说明）。
  2. 验证。node --check；本地 python3 -m http.server 8000 --directory dist；浏览器实测播放、缓存、降级；断网状态复测。
  3. 发布。按 AGENTS.md，本环境只改文件，由用户回 Qoder 说发布完成同步。dist/ 是唯一副本，改动前先在目录外备份。
  4. 清理。output/ 下三份作废视觉稿与本次试听页，待定稿后统一清理。

五、待拍板三项

  1. 发音选 A、B 还是 C。
  2. 词库重点是内容层、结构层还是规模层，或按乙到甲顺序推进。
  3. 先听 A/B 试听样本再定音质是否可接受。
