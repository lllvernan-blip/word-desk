## A. 冒烟（对照 §2.4，共 16 条）

### A1. 首次与可用性

- [ ] **1. 首次 30 秒开练**（`真机` / `本机浏览器`）  
  **怎么测**：清空站点数据 → 打开首页 → 不读外部文档 → 点主按钮开练。  
  **期望**：≤30 秒进入第一轮；能看出四阶段各自在做什么（有引导或阶段提示）。  
  **未验**：真机首次引导体感（本清单落盘时未做清空站点实测）。

- [ ] **2. 首屏响应 + 断网可续练**（`本机浏览器` + 断网；装机场景偏 `真机`）  
  **怎么测**：在线打开一次后断网刷新；点导航/主按钮看是否卡死。  
  **期望**：可点控件约 1 秒内有响应；断网刷新仍能打开并继续练习（须此前在线加载过）。  
  **未验**：真机弱网/飞行模式全路径。

### A2. P0-1 五个缺陷

- [ ] **3. 听音超时不丢输入**（`真机` · 弱网听音）  
  **怎么测**：听音卡开始输入 ≥5 个字母，人为拖慢/断音频触发约 5 秒降级重绘。  
  **期望**：降级提示出现后，已输入内容与光标仍在。  
  **未验**：弱网真机。静态侧仅确认模板回填 `card.recallTyped`（见脚本）。

- [ ] **4. 坏音频护栏生效**（`本机浏览器` / `真机`）  
  **怎么测**：对已标记坏的词再点发音。  
  **期望**：不再重复拉分片、不再重复弹失败提示。  
  **未验**：真机重复点击。脚本可验 `AUDIO_BROKEN.has(audioBrokenKey(...))`。

- [ ] **5. 过期文案清零**（`脚本`）  
  **怎么测**：全站搜「系统朗读」「选项会相应减少」。  
  **期望**：`dist/` 内均为 0 处。  
  **脚本**：`tools/smoke-static-check.sh` 已覆盖。

- [ ] **6. 桌面输入框字号**（`本机浏览器` · 1280px）  
  **怎么测**：桌面视口约 1280px，对比练习输入框与同类控件字号；核对 `styles.css` 注释与规则。  
  **期望**：桌面不再被全局 16px 放大到「两号」；注释与实际一致；iOS 防缩放另见第 16 条。  
  **未验**：1280px 目视对比。

- [ ] **7. 统计不含屏蔽/剔除词**（`本机浏览器`）  
  **怎么测**：屏蔽若干词 → 看完成页「到期 / 错题」；再撤销对照。  
  **期望**：数字与实际会出现的词一致；屏蔽后数字下降。  
  **未验**：完成页对照实测。

### A3. 备份 / 隐私 / 版本（§2.4 8–13）

- [ ] **8. 导出补全 + 恢复抽样**（`本机浏览器`；换机场景偏 `真机`）  
  **怎么测**：导出 JSON → 全新配置文件/无痕窗导入 → 抽 3 词看 `due`/`stability`。  
  **期望**：含 `userWords`、`srs`、`wrongBook`、`blocked`、完整 `settings`、`schemaVersion`；自建词与复习进度恢复且抽样一致。  
  **未验**：跨浏览器完整恢复。脚本可验导出字段名存在于源码。

- [ ] **9. 损坏备份拒写**（`本机浏览器`）  
  **怎么测**：删掉 `app` 字段 / 改坏 JSON 再导入。  
  **期望**：可读错误；不写入；不清空现有数据。  
  **未验**：手工损坏文件导入。

- [ ] **10. 清除本机全部数据**（`本机浏览器`）  
  **怎么测**：有进度后执行清除（二次确认）→ 重载。  
  **期望**：回到空库；内置约 3400 词仍在；音频缓存与坏音频名单已清空。  
  **未验**：清除后 Cache Storage / AUDIO_BROKEN 目视。

- [ ] **11. 数据与隐私页**（`本机浏览器`）  
  **怎么测**：从 footer / 设置进入「数据与隐私」。  
  **期望**：存什么 / 存哪 / 是否上传 / 怎么删 四问均有明确答案。  
  **未验**：文案通读（若入口已上线则本机可勾）。

- [ ] **12. 埋点默认关 + 导出无标识**（`本机浏览器` + 抽查 JSON）  
  **怎么测**：默认设置下看埋点开关；打开导出备份，人工扫键名。  
  **期望**：埋点默认关闭；导出 JSON 无账号/邮箱/设备标识字段。  
  **未验**：完整键名人工审计。

- [ ] **13. 版本号 + 装机 SW 更新条**（版本：`本机浏览器`；更新条：`真机` · 已安装 PWA）  
  **怎么测**：footer 与 `CONFIG.version` 对照；隐私页看 SW 缓存名；发新壳版本后打开已装 PWA。  
  **期望**：版本一致；出现「有新版本，点此刷新」；点击后练习数据不丢。  
  **未验**：装机 PWA 更新条（须真实发布/换壳后验）。

### A4. 错误态 / 听音 / 布局

- [ ] **14. 三种错误场景不白屏**（`本机浏览器` / DevTools）  
  **怎么测**：① 禁用 IndexedDB ② 首次加载断网 ③ 拦截 `audio/index.json`。  
  **期望**：各有说明，不白屏。  
  **未验**：三场景均未在本机逐条复现。

- [ ] **15. 听音无音频降级 + 语速**（`真机` · 听音）  
  **怎么测**：无音频词走听音；有音频词切 0.8× / 1.0×。  
  **期望**：无音频自动转文字并说明；`playbackRate` 分别为 0.8 / 1，实听有差异。  
  **未验**：真机听感。

- [ ] **16. 390px / iOS 聚焦 / Console**（390px：`本机浏览器`；iOS：`真机`）  
  **怎么测**：390px 宽看横向滚动；iOS Safari 点输入框；Console 看未捕获错误。  
  **期望**：无横向滚动；iOS 聚焦不放大页面；无未捕获 error。  
  **未验**：iOS Safari 真机聚焦。

**冒烟条数：16**（脚本可部分覆盖：5、及 3/4/8 的静态存在性；其余标未验直至勾选）。

## B. 发布步骤（从 `AGENTS.md` 收拢，勿另起矛盾规则）

发布源是 `dist/`。无构建步骤。非 Qoder 工具只改文件，由用户回 Qoder 说「发布」。

- [ ] **B1. 范围确认**  
  只改本目录 `dist/`（及已约定文档）；不要新建平行副本；不要改/删 `.单词翻译练习台.qoder.site`。

- [ ] **B2. 语法检查**  
  ```bash
  node --check dist/app.js && node --check dist/sw.js
  ```  
  期望：退出码 0。

- [ ] **B3. 静态冒烟脚本（可选但推荐）**  
  ```bash
  bash tools/smoke-static-check.sh
  ```  
  期望：全部 PASS。

- [ ] **B4. 递增壳缓存名**  
  改了 html/css/js/json 等静态资源后，必须把 `dist/sw.js` 的 `CACHE = 'wtp-shell-vNN'` **递增**（当前见该文件；漏递增则用户一直拿旧壳）。

- [ ] **B5. 确认 sensitive 在提交里**  
  确认 `dist/content/sensitive.json` 存在且会随发布一并带上（历史踩过未入库）。

- [ ] **B6. 音频同批（仅当重建发音包时）**  
  重建后确认 `dist/audio/index.json` 的 `v` 已递增，且与 `pack-*.bin` 同批；分片数与索引 `packs` 一致。音频 Range 不经 SW 缓存，但词缓存名跟 `index.v` 走。

- [ ] **B7. 本地主流程**  
  ```bash
  python3 -m http.server 8000 --directory dist
  ```  
  打开 http://localhost:8000，过一遍开练 / 一题 / 进度页。

- [ ] **B8. 发布前协作**  
  确认无其他 agent 同时改本目录，避免互相覆盖。

- [ ] **B9. 发布**  
  Qoder：sites-hosting 流程发布；其他工具：停在「文件已改」，等用户说「发布」。

- [ ] **B10. 发布后强刷两次**  
  线上地址强刷（硬刷新）**两次**，确认新壳生效（footer/`CONFIG.version` 或可见改动对得上）。

- [ ] **B11. 抽查音频索引**  
  打开/拉取线上 `audio/index.json`，确认 `v` 与分片仍是同批（尤其刚重建音频时）。

- [ ] **B12. 装机 PWA 抽查（若已安装）**  
  已安装客户端应出现「有新版本」提示；点刷新后数据不丢（对应冒烟第 13 条）。

**发布步骤条数：12**。
